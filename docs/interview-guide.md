# RepoScope 求职讲解与面试题

## 五分钟项目讲解

**0:00–0:40 问题。** 陌生仓库 Bug 的主要成本是定位入口、调用关系、受影响文件和证据，而不是马上写补丁。

**0:40–1:30 产品。** 输入公开 Python GitHub URL 与 Issue；系统锁定 commit，静态索引代码，让受预算约束的 Agent 调用七个只读工具，最后返回结构化报告。证据不足会明确降级。

**1:30–2:30 架构。** React 通过 REST/SSE 观察 FastAPI 的持久任务；worker 负责安全摄取、AST/关键词索引、LangGraph、checkpoint 和引用验证；PostgreSQL 保存任务、事件和报告。

**2:30–3:20 安全。** 不执行目标代码，不安装依赖，无 Shell/写工具；URL/codeload allowlist、防 ZIP Slip/符号链接/超限；固定 commit；日志和公开事件做凭据清理。

**3:20–4:20 评测。** 12 个历史 Bug 计划按 6/6 划分。Runner 只看 pre-fix case，gold 只给 scorer。指标是 FileRecall@5、MRR 和确定性引用有效率。当前槽位尚未策展、没有真实成绩，这一点公开写明。

**4:20–5:00 取舍。** 公网只放预生成 Demo，避免开放密钥成本；v1 不自动改代码或运行测试，以可解释、可复现和安全为优先。下一步是 Task 8 集成验证，而不是增加功能。

## 十个常见问题

### 1. 为什么 RepoScope 不是普通 RAG？

RAG 通常一次检索后生成答案；RepoScope 有显式状态、工具选择、预算、证据补查、批判节点、持久 checkpoint、一次反馈修订和最终确定性引用校验。

### 2. 为什么 Agent 只能使用只读工具？

目标仓库是不可信输入。执行代码或开放 Shell 会把调查工具变成供应链攻击面；自动写入也会把不确定的根因假设变成破坏性修改。

### 3. AST、关键词和向量分别解决什么？

AST 提供定义/引用/导入的结构精度；关键词处理错误文本、字符串、语法损坏和精确字面量；向量用于同义语义召回。三者互补，最终证据仍按原文校验。

### 4. LangGraph checkpoint 与 SSE 如何协作？

Checkpoint 保存可恢复的调查状态；worker 把已持久化的状态变化转换成单调事件；SSE 按序号回放。断线或刷新后，客户端从最后事件继续，而不是依赖内存流。

### 5. 为什么历史 PR 可以作为评测答案？

已合并修复提供真实开发者最终修改的文件集合，可作为检索定位的外部参照。但 PR/diff/fix 后源码只能由 evaluator 策展 gold，绝不能进入 Agent 输入。

### 6. 为什么不能只用 LLM-as-judge？

评委模型会随版本和提示漂移，且可能偏爱表达流畅而非证据正确。文件命中、行号、commit 和 excerpt 可以确定性计算；主观质量只能作为补充误差分析。

### 7. 如何防止引用不存在的代码？

每条引用携带固定 commit、规范路径、行区间和 excerpt。持久化前从同一快照重新读取并逐项比较；失败引用被移除，主假设无有效证据则降级。

### 8. 为什么公网 Demo 使用预生成案例？

避免公开模型端点消耗维护者密钥、降低滥用与数据处理风险，并让求职者无需配置即可理解交互。占位 Demo 必须清楚标注，不能伪装成真实结果。

### 9. 如何防止评测答案泄漏？

Case、result 与 gold 使用不同 JSONL 契约；runner 的函数签名不接收 gold；hidden gold 不进仓库；历史工具在离线评测中必须使用冻结的 cutoff-safe 数据或空结果。

### 10. 你如何证明结果不是编造的？

展示版本化原始结果、case digest、固定 pre-fix SHA、命令、模型标识、usage/rate card 与确定性 scorer。当前没有运行真实模型，所以项目明确报告“未执行”，不填写目标分数。
